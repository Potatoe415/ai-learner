# 0008 — All site content comes from Markdown, through a staged, stateless pipeline

Date: 2026-11-11
Status: Accepted (supersedes the content format of 0005)
Decision: Course content lives only in Markdown, in four stages that each read the previous one and write their own folder: raw sources (`RAW_content/`) → extracted Markdown (`content/01-extracted/`, script) → library notes by site category (`content/02-library/`, editorial) → one file per unit in the site format (`content/03-lessons/`, editorial) → generated typed data (`lib/generated/content.ts`, script, not committed). Specs in `content/pipeline/`.
Context: The user will supply large amounts of raw material (articles, PDFs, text files) and wants every step from raw data to site to be modular and retouchable on its own. Decision 0005 kept lessons as TypeScript objects, which tied content to code and offered no path from raw sources.
Rationale: Markdown is editable by anyone and by agents. A fixed per-kind format checked by our own small reader keeps the type guarantees 0005 wanted, with no dependency. Stages communicate only through files, with inputs recorded in `based_on` and change detection by hash (`npm run content:status`), so any stage can be rerun or hand-edited without touching the others. Editorial stages (2 and 3) are done by an agent in session following the specs; an automated LLM step can replace them later without changing the layout.
Consequences: No course text in `app/`, `components/` or `lib/`. `lib/lessons/module-N.ts` are deleted; the 8 modules were exported to Markdown and rebuild to identical data (checked on 2026-11-11). Trail, zones, modules and deliverables also move to Markdown; `lib/curriculum.ts` and `lib/lessons.ts` keep types and helpers only. `npm run dev`, `build` and `typecheck` run `content:build` first. Formats that need a tool (PDF, Word, zip) are skipped by stage 1 until a dependency is approved. The site still shows one trail; the build rejects a second.
Alternatives_Rejected: MDX (new dependencies, content mixed with components). A Markdown library such as remark (dependency for a format we fully control). One script running all stages (a failure or edit in one stage would force rerunning everything). Keeping TypeScript content and adding Markdown only for new material (two sources of truth).
